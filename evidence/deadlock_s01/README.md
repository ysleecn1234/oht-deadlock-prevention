## 교착 2건

### 1,500대 — 중앙통로 1

- 발생 t=9,177초, **6대**, 600.8초 연속 정지, 영향 0대
- 노드: 008536 / 007765 / 008385 / 007805 / 007763 / 008564
- OHT: 83 / 1282 / 1368 / 300 / 291 / 370
- 6개 중 3개가 합류 노드
- 왕복 2차선 + 양 끝 U턴 구조의 고리를 빈칸 없이 채움

### 2,000대 — 베이 3 + 중앙통로 1 진입부

- 발생 t=6,899초, **18대**, 600.0초 연속 정지, 영향 21대
- 합류부 81 · 114 포함
- 왼쪽 차선 9대 상행 + 오른쪽 차선 9대 하행, 위아래 U턴으로 연결
- 고리 바깥 21대가 추가로 막혀 베이 3이 마비

## 왜 풀리지 않는가

두 건 모두 다음이 성립합니다.

1. **우회 불가** — 순환 구성원 전원이 나가는 길이 하나뿐인 노드(out-degree 1)에 있습니다. 재탐색 코드는 `OUT_LINKS` 중 현재 진행 방향이 아닌 링크를 찾는데, 그런 링크가 존재하지 않습니다.
2. **비켜주기 불가** — `request_yield()` 는 유휴 차량에게만 요청합니다. 구성원 전원이 작업 중입니다.
3. **예약 반납 무의미** — 막혔을 때 놓는 것은 아직 진입하지 않은 예약 노드이며, 자기가 선 노드는 계속 점유합니다.
4. **고리 제어 범위 밖** — 두 건 모두 탐지된 베이 고리 77개 어디에도 속하지 않습니다(`detected_ring_ids` 가 빈 배열).

## 검증 방법

`dnd_work/verify_deadlock.py` 는 탐지기와 별개 프로그램입니다. 결과 JSON에서 노드 목록만 꺼낸 뒤 시뮬레이터 지도 데이터를 새로 불러와 직접 대조합니다. 탐지기에 버그가 있어 엉뚱한 것을 교착으로 찍었더라도 이 검사에서 걸러집니다.

시뮬레이터가 지도 파일을 파일명만으로 열기 때문에 **반드시 `dnd_work/` 안에서 실행**해야 합니다.

```bash
cd dnd_work
RESULT_JSON_PATH=../evidence/deadlock_s01/s01_oht1500_interval0.45_fix_on.json \
  python3 verify_deadlock.py
```

두 건 모두 전 항목 통과했습니다. 출력은 `verify_oht1500.txt` / `verify_oht2000.txt` 에 있습니다.

| 검사 | 1,500대 | 2,000대 |
|---|---|---|
| 구성원 노드가 모두 다르다 | 6개 중 중복 0 | 18개 중 중복 0 |
| 전원이 1~2홉 안에 앞차를 둔다 | 1홉 4 / 2홉 2 | 1홉 16 / 2홉 2 |
| 전원이 나가는 길이 하나뿐인 노드에 있다 | 6 / 6 | 18 / 18 |
| 탐지된 베이 고리 밖이다 | 고리 노드 0개 | 고리 노드 0개 |
| 전원이 600초 이상 연속 정지했다 | 600.8초 | 600.0초 |

**이 검사로 증명되지 않는 것**: 기록을 남긴 시점 이후에도 계속 멈춰 있는지는 알 수 없습니다. 탐지기가 600초에서 실행을 중단했기 때문입니다. `STOP_AFTER_SECONDS=0` 으로 다시 돌려 관측해야 하며, 별도 진행 중입니다.

## 재현 방법

케이스는 결정론적으로 생성되므로 같은 파일이 다시 만들어지고, 같은 교착이 같은 시각에 재현됩니다.

```bash
cd dnd_work
CASE_NUMBERS=1 python3 generate_case_files.py

CASE_DIRECTORY=../cases/s01 OHT_COUNT=1500 SIMULATION_HOURS=6 \
  RESULT_JSON_PATH=../runs/확인.json python3 deadlock_detector.py
```

1,500대는 t=9,177초, 2,000대는 t=6,899초에 교착이 잡히면 동일 환경입니다.
