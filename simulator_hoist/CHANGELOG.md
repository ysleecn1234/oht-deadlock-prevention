# 중앙통로 호이스팅 정지 실험 추가

## 목적과 기준

팀원의 f71735e 버전에서 기존 로트 스케줄과 선로를 유지하면서, 중앙통로의 유한한 호이스팅 정지가 데드락 후보 발생에 미치는 영향을 비교한다. 실제 호이스트 기구·버퍼 보관 작업을 모델링한 것이 아니라 지정 주행 노드에서 서비스 정지를 추가하는 실험이다.

기준 버전의 차간거리 검사 범위 수정, 1,150mm 최소거리, 출발 노드 조기 반납, 막힘 정지 사전감속 및 탐지기를 포함한다. 다른 로컬 작업의 모든 변경을 합친 것은 아니다. 기존 dnd_work/를 수정하지 않고 독립 실행 폴더로 추가했다.

## 동작 변경

- 모드 0: 기존 동작. 모드 1/2/3: 각각 017192/016911/017024. 모드 4: 세 지점 모두.
- 세 노드는 중앙통로 2의 일반 주행 노드다. 포트 접근/transfer 노드와 원본 20,000건 스케줄의 출발·도착지를 제외하여 기존 상하차와 분리했다.
- 적재 운반 작업에서만 호이스팅을 판정한다. SHA-256에 전용 시드, 로트 ID, 운반 구간 ID, 노드 ID, 실제 방문 순번을 넣고 발생 확률과 비교한다. OHT 번호·실행 모드·공유 난수를 사용하지 않는다.
- 경로 재탐색이나 락 획득 재시도는 새 방문으로 세지 않는다. 모드가 달라도 동일 식별 방문의 판정은 같다. 다른 정지로 인해 경로·시각이 달라지는 것은 가능하다.
- 도착 전 감속, 도착 속도 0 확인, 현재 노드 점유 유지, 지정 시간 대기 후 재출발. 외부 깨우기 신호가 대기 시간을 단축하지 않도록 처리했다.
- 추가 호이스팅 시간을 기존 loadunload와 분리하고 active 통계에 포함했다. 정상 호이스팅을 자체 락대기 상태로 표시하지 않는다.
- 결과 JSON에 모드·확률·시드·대기시간·방문 판정·차량/작업 식별자·시작/종료 시각을 저장한다.

## GUI와 실행

view_hoist.py는 원본 pygame 화면에 H1/H2/H3 지점 표시, 수행 중 색상, 설정과 이벤트 수 표시, 종료 시 이벤트 저장을 추가한다. 원본 탐지기와 같은 대기열 상한 및 스케줄 소진 보호를 적용한다. GUI는 관찰용으로, 데드락 자동 종료/분석 결과는 deadlock_detector.py 실행을 사용한다.

기본 호이스팅 확률 10%, 8초, 시드 42는 조절 가능한 초기값이다. 본 실험의 확정값이나 실측값으로 주장하지 않는다. 모드 비교 시 이 값과 OHT 대수 및 케이스를 동일하게 유지한다.

## 검증과 한계

- 단위 테스트: 모드 독립 판정, 재탐색/방문 카운트, 출발·목적지 제외, 감속 제한, 확률 경계와 입력 검증.
- 실제 지도/주행 코드의 세 지점 경로: 모드 0~4, 정지 속도 0, 8초 서비스, 노드 점유 유지, 외부 wakeup에도 서비스 시간 유지.
- 별도 프로세스 반복 실행의 이벤트 로그 일치 및 단독/복합 모드의 동일 방문 판정 일치.
- OHT 20대/시뮬 120초에서 원본과 모드 0 결과 일치(실제 실행시간 관련 값 제외).
- GUI 1,000대 렌더 스모크 검증 및 실행 확인.

대규모 다중 시드 데드락/충돌 탐색은 아직 수행하지 않았다. 기존 라우팅 비용과 배차 ETA는 추가 호이스팅 시간을 예측하지 않으며, 실제 주행에서 정지 제약을 적용한다. 기본 투입 설정은 8,000건/h 시도율이며 대기열 상한 2,000건에서 투입을 미루므로 실제 투입률 보장과 다르다.

검증 명령 및 재현 조건은 README.md를 따른다. 실행 결과·개인 로컬 경로가 든 로그·캐시는 커밋하지 않는다.
